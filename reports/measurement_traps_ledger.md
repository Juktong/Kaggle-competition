## Pre-flight — ordered by recorded recurrence

Frequency counts manifestations, not severity: the bad append expression counts as seven file losses, while
one smoke that gave several wrong statistics counts as one incident.

1. **Preserve the record and make the process observable (7 truncated reports; 2 buffered launches; PID/self-match recurred).** Append with `scripts.append_section.append` (or read and close before opening for write); launch redirected Python as `python3 -u ... | tee ...`; retain the launch PID and confirm it with `ps -o pid,ppid,etime,cmd -p PID` before signalling it. Do not use `pkill -f`, a waiter whose command contains its own pattern, or a producer piped directly to `head`. Capture producer output first, then shorten it.
2. **Do not read a smoke as an effect size or conclusion (5 explicit reversals: N1, Q11, Q21, Q56, Q57).** A smoke proves imports, data, patch activation, alignment, output, and sane ranges only. For an alignment conclusion use at least 40 held-out wells; otherwise use the planned full population. Report per-well median/win rate and the 3-well draw before interpreting pooled RMSE.
3. **Use the independent unit that will be scored (3 distinct unit errors).** Split by well, never by row or pair; bootstrap 3 wells, not 760; for a well-level segment use `n_wells`, not rows, and compare its spread with `sigma_well/sqrt(n_wells)`. Run `scripts/eval_three_well_gate.py` for a submission candidate.
4. **Reproduce the unmodified deployed quantity before measuring a delta (at least Q21, Q46, Q58).** Join on `(well, ridx)`, assert truth equality and full coverage, recover/check constants from the deployed output, and require the OFF/control path to match exactly or to a declared rounding tolerance. A column name, file label, or API default is not provenance.
5. **Prove the treatment is reachable and active (N1, Q54, Q57).** Include an exact degeneracy limit, then report changed rows, binding fraction, selected-state activation, and dose response. Zero movement means “inert/unreachable”, not “no effect”.
6. **Score the final objective and accumulated action (Q13, Q17, Q40).** AUC, pointwise argmax error, objective cost, and per-step magnitude are diagnostics only. Run the DP/final pipeline and, for directional path terms, report `abs(estimate) * steps`.
7. **Keep selection and attribution out of the scored sample.** Choose hyperparameters on disjoint wells and score on held-out wells; preserve the averaging/shrinkage baseline; change one active factor; never derive a calibration signal and its target from the same truncated run. Treat a public regression as information under Policy Rule 3, not as noise to explain away.

## Enforcement status

**Present in code (at the named call sites, not as a repository-wide framework):** `scripts/eval_three_well_gate.py`
implements Policy Rule 1; Q36/Q56/Q58 check `(well,ridx)` alignment and truth equality; Q56 derives its
trellis twin through unique anchored insertions and requires `np.array_equal` against the deployed PF, and
Q58 reruns that control; Q57 asserts the zero-dip degeneracy; `scripts.append_section.append` reads and
closes before writing. These checks fail loudly where those scripts are used.

**Convention only — a reader must still remember these:** smoke is activation-only; >=40/full-scale and
nested-by-well interpretation; well-level effective sample size; Policy Rule 3’s reading of public loss;
preserving the averaging baseline; scoring DP/final output rather than a proxy; accumulated-pull reporting;
generic binding/activation checks; deployment-source and submitted-version provenance; one-active-factor
attribution; independent calibration signal/target; `python3 -u`; retained/verified PIDs; and avoiding live
producer-to-`head` pipelines. The Q58 gate-source check is also not encoded as schema provenance, so a new
consumer can still select the wrong columns unless it first reproduces the deployed output.

This ledger changes no technical conclusion or slot recommendation.
