# L4 + K=96 seeds-only combination (2026-07-21)

Task 2 of the parallel queue. Status: **validated, does not meet the bar for a new submission.**
Script: `scripts/l4_k96_combo.py`.

## Question

The K=96 top-K **ranker** did not pass the gate (`reports/topk_path_ranker_final_2026-07-21.md`:
bootstrap 5th −0.0158, no constructible guard). But the **seeds-only** effect — simply using more PF
seeds in the likelihood-weighted mean, with no ranker and no new model — was positive. Does that
seeds-only effect survive on top of the anisotropic field already submitted as `54878409`?

## Two independent reasons not to submit

**1. The increment is not stable.** Against `54878409` the bootstrap 5th percentile is **−0.0418** with
only 73% of well-resamples positive. A +0.0278 point estimate with that spread is the same shape as the
top-K candidate that was already held back.

**2. The measured increment is inflated by a baseline mismatch.** Reading the deployed kernel:

```python
PF_NS = int(_os.environ.get('PF_NS', '64'))   # OOF used 24; 64 = slightly better PF, feasible at rerun
```

**Inference already runs 64 seeds**, while the OOF this comparison is built on used 24. So the
+0.0432 base-level seeds-only effect measured here is the **24 → 96** difference, whereas deploying K=96
would only buy **64 → 96**. Under ~1/√N variance reduction, 24 → 64 captures most of the available
effect and 64 → 96 adds little. The honest expected increment over what is already deployed is therefore
materially smaller than +0.0278, and +0.0278 is itself unstable.

Runtime was *not* the blocker: the full kernel log shows PF at NS=64 taking ~45 s for 3 test wells
(t=463.8 → 508.3), so NS=96 would be ~68 s. Cost is affordable; the gain is not there.

## Disposition

Recorded as validated-negative. It does not qualify for a submission slot while `54878409` is pending —
it is also not independent of `54878409` (same L4 field, only the PF seed count differs), so it would
fail the independence condition even if the increment had been stable.
